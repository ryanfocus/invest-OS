## 2026-08-17（一）的驗證計畫

⚠️ **兩支工具都會登入群益，不要同時跑**（同一組帳密兩個連線可能互踢）。
照下面的順序，一支跑完再跑下一支。

### 08:44 起 — `compare_open.py`（約 1 分鐘）

```
python tools/compare_open.py
```

驗的是：**群益的 `nOpen` 在盤中是否等於期交所的開盤價**。
先前 2026-08-10 實測差 2 點（44987 vs 44985），但所有樣本都是收盤後取的。

它並列三個來源：`nOpen` 欄位、第一筆非模擬成交（帶時間戳）、期交所。
結果會**附加**到 `captured/open-price-samples.jsonl`——這是新增的，
原本只印在終端機，跑完關掉視窗證據就沒了。

判讀：
- 三者一致 → `nOpen` 可信，這個 blocker 解除
- `nOpen` 與另兩者不一致 → **blocker**，開盤價要改用第一筆真實成交

### 之後任何盤中時間 — `verify_order_path.py`

```
python tools/verify_order_path.py --listen 900
```

驗的是：**成交回報的欄位位置**（我從官方文件的欄位排列推的，沒驗過）。

跑起來之後，在群益 APP **下任何一筆單**——你本來就要做的交易也算數，
工具只是在旁邊聽，不影響那筆交易。

判讀：
- 解讀出來的「數量」等於實際成交口數 → 欄位位置對
- 顯示「認不出來」→ 形狀檢查擋下了，欄位推錯 → **ticket 09 的前提要重寫**
  （09 假設推播大部分時候會成功；若從來認不出來，那個假設不成立）

### 這兩項都過了，才輪到花錢的

**實機里程碑**：1 口微台，程式 08:50 進、程式 13:40 出，你在旁邊看著。
