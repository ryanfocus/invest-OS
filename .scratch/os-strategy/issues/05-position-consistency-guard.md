# 05 — 部位一致性防護

**What to build:** 系統**絕不在「不確定自己持有什麼」的狀態下靜默結束**。
送單後收不到成交回報、或平倉後還有殘留口數，都要留下明確記錄並發 Discord 要求人工介入。

這是本系統唯一會直接虧錢的失效模式：帳上有部位、程式卻不知道，於是 13:40 不會去平它，
部位就這樣進了夜盤（15:00–05:00），而使用者完全不知情。

**Blocked by:** 04

**Status:** ready-for-agent

## 送單後收不到成交回報

- [ ] 送出進場委託後，在設定的時限內未收到成交回報 → 狀態檔記為**「不確定」**
      （已送單、成交口數未知），並發 Discord 要求人工確認帳戶
- [ ] 狀態為「不確定」時，出場那班**不自動送出任何委託**，改發 Discord 要求人工處理
      —— 不知道持有幾口就下單，可能開出反向新倉，比什麼都不做更糟
- [ ] 逾時秒數由設定檔決定，且該設定確實被程式讀取（沿用既有的設定漂移檢查）

## 平倉後仍有殘留

- [ ] 出場後比對「應平口數」與「實際成交口數」，有殘留 → 發 Discord 告警，
      訊息含商品、方向、**殘留幾口**，足以讓使用者直接手動處理
- [ ] **部分成交不視為出場成功**，狀態檔不可標記為已出場

## 通用

- [ ] 上述所有行為在假 broker 上完整可測，不需真實 COM 或帳號

---

**為什麼獨立成一張**：這兩件事看起來分屬進場與出場，實際是同一個失效模式的兩面——
**系統以為的部位 ≠ 帳戶實際部位**。放在一起才能用一致的方式處理（記錄不確定性、
交給人判斷、絕不猜測），拆開容易各做各的。
