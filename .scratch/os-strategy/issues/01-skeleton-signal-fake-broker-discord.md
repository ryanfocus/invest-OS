# 01 — 專案骨架 + 訊號計算 + 假 broker + Discord

**What to build:** 執行一次進場流程，程式從假 broker 取得大台、小台、微台的開盤價，
判斷出當日訊號方向，並把三個開盤價與方向發到 Discord。整條鏈端到端可跑通，只是資料是假的。

這是整個專案的第一顆曳光彈——之後每一張 ticket 都是把這條鏈上的某一段換成真的。

**Blocked by:** None — can start immediately

**Status:** done（`f36d66d` + `b0369b4`，36 tests passed）

- [x] 執行進場流程後，Discord 收到一則訊息，內含三個商品的開盤價與訊號方向
- [x] 大台開盤價同時大於小台與微台 → 訊號為**做多**
- [x] 大台開盤價同時小於小台與微台 → 訊號為**做空**
- [x] 其他所有情況 → 訊號為**不動作**
      —— 規則是「大台**同時**大於另兩者」或「大台**同時**小於另兩者」。
      大台與小台相等、大台與微台相等、三者相等，都不成立 → 不動作。
      ⚠️ 但**小台與微台彼此相等**時規則仍然成立：大台高於兩者 → 做多，低於兩者 → 做空。
      （實測 126 個交易日中此情況佔 20 天／15.9%，不是邊緣案例）
- [x] 訊號計算為純函式，不做任何 I/O，可獨立測試
- [x] 假 broker 可由測試指定它要回傳的三個開盤價
- [x] Discord 通知可由設定開關關閉；關閉時不發出任何 HTTP 請求
- [x] `settings.yaml` 的每個設定項都有對應程式讀取
      —— 改為結構性檢查：追蹤 `build()` 實際讀取的 key，與 yaml 的 key 集合比對，
      不需人工維護清單。兩個方向都擋（孤兒設定、幽靈讀取）。
- [x] 全部測試在**未安裝群益 COM 元件**的機器上可通過（本機 COM 未註冊，36 passed）

## 完成後的偏差記錄

1. **`broker` 與通知改用依賴注入**，而非 SPEC 原本寫的 monkeypatch。
   理由與修訂已記在 `docs/SPEC.md`《模組劃分》。

2. **「相等」的措辭原本寫錯**（ticket / CONTEXT / SPEC / REQUIREMENTS 皆有）。
   原文說「兩兩相等 → 不動作」，但規則是公式 `大台 > 小台 and 大台 > 微台`；
   小台與微台彼此相等不影響該公式成立。程式行為未變，錯的是說明文字。
   ✅ 2026-08-02 已確認採用公式解讀，記於
   [ADR-0004](../../../docs/adr/0004-ties-between-mtx-and-tmf-still-produce-a-signal.md)。
