# 02 — 真實 broker：登入與取得開盤價

**What to build:** 把假 broker 換成真的群益 API。程式用設定檔裡的帳密自動登入、
訂閱三個商品、取得當日開盤價，Discord 收到的是**真實數字**。人不需要在場、不需要輸入任何東西。

這張是全案的閘門：它同時回答「微台的商品代號是什麼」和「開盤價是日盤還是夜盤」，
後者沒確認之前，後續所有下單功能都不該啟用。

**Blocked by:** 01

**Status:** done（2026-08-09，60 tests passed，實機驗證 + code-review 修正完成）

- [x] 程式以設定檔中的帳密自動登入，全程不需人工輸入驗證碼或點選視窗
- [x] 取得三個商品的開盤價，數值已還原小數（群益回傳為整數且放大 100 倍）
- [x] 開盤價為 0 視為「資料未就緒」，等待一分鐘後重試，最多三次
- [x] 開盤價不落在跌停價與漲停價之間時同樣視為未就緒並重試
- [x] 三次重試後仍取不到 → 發 Discord 告知當日無訊號，程式正常結束
- [x] COM 元件的初始化**不在模組載入時發生**；未註冊 COM 的機器仍可 import 並執行全部測試
- [x] 微台的商品代號已由商品清單查詢實機確認，結果更新回 CONTEXT.md
- [x] 開盤價已與期交所官方資料對照，**確認為 AM 盤（日盤）而非全盤**，結果記錄在案
- [ ] 假 broker 與真實 broker 通過同一組行為測試
      ⚠️ **未完成**：兩者共用 `build_open_prices` 的判定邏輯（結構上保證一致），
      但尚未建立「同一組測試跑兩次」的雙軌執行機制。需要 COM + 帳號，留待 ticket 08（已在該張列為驗收條件）。

### 重試真的會再試（不只是設定寫著）

- [x] 前兩次取值「未就緒」、第三次成功 → **訊號正常產生**
- [x] 一直未就緒 → Discord 收到「今日無訊號」，程式正常結束
      （不斷言重試間隔或呼叫次數——那是實作細節；重試間隔的值由設定漂移檢查守）

### 缺一不可與失敗路徑

- [x] 三個商品**只取到部分**（例如微台失敗）→ 不產生訊號，Discord 告知缺哪一個
      （訊號需要三個價才能比大小，缺一個就不是「不動作」而是「無法判斷」）
- [x] **登入失敗**（密碼錯、聲明書未簽、憑證過期等）→ Discord 告知並以錯誤結束，
      不靜默結束——靜默會讓人以為今天只是沒訊號

### 盤別不可被誤改（守 ADR-0005）

- [x] 有測試守住**商品代碼必須帶 `AM` 後綴**。期望值來自 2026-08-07 實測
      （三商品 `nOpen` 與期交所一般時段完全一致），非憑空斷言
- [x] 漲跌停不變量使用**同一代碼自己的**漲跌停，不與其他盤別混用
      （實測 AM 盤 48990／40084、全盤 48683／39833，混用會誤判）
