# invest-os

台指期當沖策略的自動執行程式。每天早上比三個開盤價決定做多或做空，
下午收盤前平掉，**部位不過夜**。

跑在一台 Windows 電腦上，由 Windows 工作排程器每天叫醒兩次。你不需要做任何事，
只要看 Discord。

---

## 它每天做什麼

| 時間 | 動作 |
|------|------|
| **08:50** | 取大台、小台、微台的開盤價 → 算訊號 → **發 Discord** → 依訊號下單 |
| **13:40** | 送出等量反向委託平倉 |

訊號的規則只有三行：

```
大台開盤價 > 小台 且 > 微台   →  做多
大台開盤價 < 小台 且 < 微台   →  做空
其他（夾在中間）              →  不動作
```

只看 **08:45 那一個成交價**，盤中怎麼走與這個策略無關。

⚠️ **結算日不出場**，讓它進結算現金交割（那天 13:30 就停止交易，送單也送不出去）。

---

## 你每天會看到什麼

**早上一則訊號訊息 = 一切正常。**

```
2026/08/25 OS
大台開盤：44488
小台開盤：44520
微台開盤：44501
訊號：做空
```

下午正常出場**不會**發訊息 —— 沒消息就是好消息。

收到其他訊息時 → **[訊息對照表](docs/MESSAGES.md)** 告訴你那是什麼、你要做什麼。

⚠️ **平日早上沒收到訊息 = 排程掛了。** 那是唯一的偵測機制，刻意不做心跳
（每天那則訊號本身就是心跳）。處理方式見 [DEPLOY.md](docs/DEPLOY.md)。

---

## 你會動到的東西

| 我想… | 去哪 |
|-------|------|
| 改標的、口數、開關 | [`config/settings.yaml`](config/settings.yaml) — 每一項都寫了設錯會怎樣 |
| 填帳號密碼 | `.env`（複製 `.env.example`，**不進版控**） |
| 看今天發生什麼 | `logs/entry-YYYYMMDD.log`、`logs/exit-YYYYMMDD.log` |
| 重建排程 | `.\tools\setup_schedule.ps1`（`-Show` 只看現況） |

⚠️ **`logs/` 不要整包傳給任何人。** 裡面有券商回覆的原始字串（含期貨帳號）
與群益元件自己寫的日誌（含身分證字號）。它已經排除在版控外，30 天自動清除。

---

## 出事的時候

1. **看 Discord 那則訊息** → [訊息對照表](docs/MESSAGES.md)
2. **看當天的 log** → `logs/entry-YYYYMMDD.log`
3. **換電腦、重裝、憑證過期** → [DEPLOY.md](docs/DEPLOY.md)
4. **登入或憑證問題** → [LOGIN_SETUP.md](docs/LOGIN_SETUP.md)

> 📌 **這個系統對「不確定」的態度是：不猜，叫人。**
> 分不清帳上有幾口的時候它不會自動送單，而是發訊息請你確認。
> 所以收到「不確定」類的訊息不是故障，是它在照設計運作。

## 給接手開發的人

| 文件 | 內容 |
|------|------|
| [CONTEXT.md](CONTEXT.md) | 詞彙表。「開盤價」「不確定」「結算日」在這個專案裡精確指什麼 |
| [docs/SPEC.md](docs/SPEC.md) | 完整規格與驗收條件，含測試策略與接縫的選擇 |
| [docs/adr/](docs/adr/) | 五個架構決策與**為什麼不選另一條路** |
| [docs/DEPLOY.md](docs/DEPLOY.md) | 換機器要重做的七個步驟 |
| `tests/fixtures/` | 券商回來的**真實**字串。測試的期望值來自它們，不是來自推導 |

```powershell
.\.venv\Scripts\python.exe -m pytest -q      # 全部測試
.\.venv\Scripts\python.exe tools\verify_order_path.py --listen 5   # 唯讀，不會下單
```

⚠️ 測試全綠**不代表能連上券商** —— 那五百多條跑的是假 broker。
真正的驗證只能靠實機，而歷次實機發現的事實都記在 `tests/fixtures/` 的檔頭。
