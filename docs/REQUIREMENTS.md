> 建立日期：2026-08-01 ｜ 來源：與策略作者的 LINE 對話

## 0. 一句話

每個交易日早上比較**大台、小台、微台的開盤價**，決定當天做多／做空／不動作，
08:50 進場、13:40 出場，不留倉過夜；訊號發到 Discord，自動下單為可選功能。

---

## 1. 策略邏輯

三個商品**都取開盤價**（08:45 開盤產生的價格）比大小：

| 條件 | 動作 |
|------|------|
| 大台開盤價 **>** 小台開盤價 **且** 大台開盤價 **>** 微台開盤價 | **做多** user 設定的台指期 |
| 大台開盤價 **<** 小台開盤價 **且** 大台開盤價 **<** 微台開盤價 | **做空** user 設定的台指期 |
| 其他（大台與小台或微台相等時亦屬此列） | **不動作** |

**要嘛純大於、要嘛純小於**——只要不是全部同向，就沒有單。
大台開盤價夾在小台與微台之間 → 不動作。

比完就定案，**盤中不再比價、不盯盤**。

## 2. 時間表

| 時間 | 事件 | 失敗處理 |
|------|------|---------|
| 08:45 | 開盤，產生開盤價 | — |
| **08:50** | **進場** | 延後 1 分鐘重試，**共 3 次** |
| **13:40** | **出場**（多→賣、空→買回） | 隔 1 分鐘重試，**共 3 次** |
| **13:30**（**僅結算日**） | **出場** | **不重試**（見 §9） |

- **不留倉過夜**，每天早上都是空手狀態
- **結算日出場時間提前到 13:30**（見 §9）
- **非交易日不執行**（見 §10）
- 08:45→08:50 的 5 分鐘落差是**刻意設計**，策略作者的兩個理由：
  1. 開盤第一分鐘價差很大
  2. 開盤價本來就無法提前確定，「就犧牲前 5 分鐘」
- 回測資料即是以 08:50 進場計算

## 3. 交易標的與口數

- **訊號來源**固定是大台、小台、微台三者的開盤價
- **實際下單標的**（大台／小台／微台）由 user 設定
- **口數**由 user 設定
- **槓桿最高 3 倍**——由 user 自己算好填口數，**系統不做檢查、不做保證金試算**
- 合約：**近月合約**

## 4. 部位隔離（重要）✅ 已確認

> 「只出場 OS 策略 user 設定的台指期，**原本就持有的台指期不要動他**」

**規則：OS 一律進出「user 設定的口數」，不因帳上既有部位做任何調整。**

- 進場：送設定口數（方向依訊號）
- 出場：送**相同口數**的反向單
- **不需要**額外補買／補賣使用者原有的部位——算術上會自然回復

策略作者確認的情境（原有 +1 微台固定持有，OS 設定 3 口，當日做空）：

| 時間 | 動作 | 帳戶淨部位 |
|------|------|-----------|
| 開盤前 | 使用者固定持有 | **+1** |
| 08:50 | OS 賣 3 | +1 − 3 = **−2** |
| 13:40 | OS 買回 3 | −2 + 3 = **+1** ✅ |

→ 系統必須**自行記錄本次進場的方向與口數**，出場時據此送對等反向單，
　 **不能依賴「帳戶總部位」來決定平倉數量**（帳戶只看得到淨額，見 §12）。

|------|------------------------|------------|------|
| 大台 | **`TX00AM`** | `FITX` | ✅ 2026-08-07 實機確認 |

### 下單參數（與部位隔離直接相關）

下單結構為 `sk.FUTUREORDER()`，其中 `sNewClose` 為倉別：

| 值 | 意義 |
|----|------|
| 0 | 新倉 |
| 1 | 平倉 |
| 2 | 自動 |

> ⚠️ **`sNewClose` 該填什麼，必須實機驗證，不要照抄。**
>
> 若使用者原本持有**反向**部位，OS 的進場單會跨越既有部位
> （例：帳戶 +1，OS 要賣 2）。此時：
> - 填 `0`（新倉）→ 券商可能**拒單**，因為前 1 口實質上是平倉
> - 填 `2`（自動）→ 系統自行拆成「平倉 1 + 新倉 1」，可送出
>
> 兩者的**經濟結果相同**（淨部位都變 −1），差別在券商如何記帳、保證金與當沖認定。
> 由於無法從文件確定群益的實際行為，**規格階段須在測試環境實測**：
> 帳上先建立反向部位，再送跨越部位的委託，確認 `0` 與 `2` 各自的結果。

## 9. 結算日處理 ✅ 已決議

**結算日照跑，但出場時間改為 13:30。**

原因：臺灣期貨交易所官方規格（[臺股期貨 TX](https://www.taifex.com.tw/cht/2/tX)）：

> 「一般交易時段之交易時間為營業日上午8:45~下午1:45」
> 「**到期月份契約最後交易日之交易時間為上午8:45~下午1:30**」
> 「到期月份契約最後交易日無盤後交易時段」

結算日（每月第三個星期三）近月合約 **13:30 停止交易**，13:40 送不出出場單。
若放著不管會走現金結算，結算價是「當日 13:00–13:30 **加權指數**每筆成交價的簡單算術
平均」——那是現貨指數不是期貨價，出場價將脫離策略控制。

**因此：結算日當天，出場時間為 13:30（而非 13:40），且不做重試。**

### 為什麼結算日不重試

結算日 13:30 之後合約已停止交易，重試必然失敗；而且**未平倉部位會被交易所自動
現金結算**，部位不會被留下來。這是交易所規則，不需要程式介入。

→ 結算日出場為**單次嘗試**，失敗即由結算機制處理，不重試、不告警。

> 📌 **對帳時要記得**：自動結算的成交價是「當日 13:00–13:30 **加權指數**每筆成交價的
> 簡單算術平均」，是**現貨指數**而非期貨價。若結算日的 13:30 出場單沒成交，該日實際
> 損益會與「用期貨價計算的回測」有落差。這不影響策略運作，但事後比對績效時
> 若發現結算日對不上，原因通常在這裡。

### 結算日的判定來源

`SKQuoteLib_RequestStockList(2)` 回傳的商品清單含 **`最後交易日`** 欄位
（格式如 `20180719`），可直接用 API 自身的資料判定，不必自行推算「第三個星期三」。

## 11. 出場失敗告警 ✅ 已決議

**13:40 三次出場都失敗 → Discord 發通知。**

理由：一般交易日沒有任何機制會幫你把部位收掉，失敗就是實際帶著部位進夜盤
（15:00–05:00）。這與結算日不同——結算日有交易所現金結算兜底。

### 📌 告知事項：固定持有部位在做空日會被沖銷再重建

**這不影響程式邏輯，也不需要任何額外處理**（§4 的規則已經完備）。
列在此處是因為它是一項**實際成本**，使用者應知情。

台灣期貨**同一帳戶、同一商品、同一契約月份的部位是淨額計算**，多空無法並存
（「做同商品同契約，國內券商是沒辦法同時有多單與空單的，因為一多一空是平倉」）。

因此 §4 表格中「淨部位 −2」的真正意義，**不是**「使用者的 +1 和 OS 的 −3 分開存放」，
而是券商記帳上：

1. 08:50 賣 3 口 → 先**平掉**使用者那口多單（損益當場實現），再新倉 2 口空
2. 13:40 買 3 口 → 平掉 2 口空，再**新倉 1 口多**

→ 13:40 回來的 `+1`，是以 **13:40 價格重新建立的新部位**，不是早上那一口。

**實際成本：**

| 項目 | 影響 |
|------|------|
| 成本基礎 | 固定持有部位的進場價每個做空日被重設為當日 13:40 價 |
| 交易成本 | 多一趟手續費 + 期交稅（被迫的平倉再建倉） |
| **不對稱** | **只有做空日會發生**。做多日 `+1 + 3 = +4` 不觸發沖銷，固定部位完全不受影響 |

若使用者在意「從某價位長抱至今」的連續性，該數字會在每個做空日被打斷。

**唯一能真正隔離的方式是用另一個期貨帳號跑 OS**（同券商開第二個帳號，或用不同券商）。
此為使用者的取捨，非技術限制。

### ⚠️ 最大的實務風險：狀態遺失

由於帳戶只看得到**淨部位**，看不到「哪幾口是 OS 的」，一旦 OS 的狀態檔遺失或損毀，
**就無法得知該平幾口**。淨部位 −1 有可能是「OS 空 1」，也可能是
「使用者多 1 + OS 空 2」——兩者外觀完全相同。

→ 狀態持久化的可靠度，是這個系統最關鍵的單點。
