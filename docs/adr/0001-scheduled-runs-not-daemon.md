# 用兩次排程觸發，不做常駐程式

進場 08:50、出場 13:40，中間隔近 5 小時。我們選擇由 Windows 工作排程器**各叫醒一次短命
process**，而不是跑一支從早活到收盤的常駐程式；兩次執行之間的部位資訊靠 `state/position.json`
傳遞。

決定的理由是**這個策略盤中完全沒有邏輯**——沒有停損、不看盤、不改單，所以常駐買不到任何東西，
卻要多扛斷線重連、COM 訊息幫浦、記憶體管理。更關鍵的是失效模式：常駐程式若在 10:00 當掉，
**沒有任何東西會在 13:40 幫你出場**；排程模式下 13:40 那班車照樣會來。

## Consequences

- 13:40 需要重新登入。這不是額外成本——群益的登入 token 本來就有時效
  （錯誤碼 1109 `SK_ERROR_THERE_IS_NO_TOKEN`「因登入未取得時效token，請重新登入」），
  掛著 5 小時反而可能過期。
- 狀態檔成為系統的單點：13:40 那個 process 唯一知道「今天開了幾口、什麼方向」的來源就是它。
  帳戶查詢救不了，因為台灣期貨採淨額計算，帳上的 −2 可能是「OS 空 2」也可能是
  「使用者多 1 + OS 空 3」。
- 登入是純程式呼叫，不需要人在場：雙因子的第二因子是**安裝在機器上的憑證**，
  不是每次要輸入的驗證碼。
