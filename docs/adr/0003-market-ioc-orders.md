# 進出場一律市價 + IOC，不使用 ROD

進場與出場都送**市價（`bstrPrice = "M"`）搭配 IOC（`sTradeType = 1`）**，並且明確
**不使用 ROD**。

排除 ROD 的理由不是價格，是**狀態確定性**：ROD 會掛在委託簿上。程式送出後若當下未成交，
會判定為失敗並記錄，但那張單可能三分鐘後才成交——**帳上多出部位而系統不知道**。
對一個必須精確記得「自己開了幾口」的系統（見 SPEC 的「部位隔離」），這是致命的。
IOC 保證「要嘛立刻成交、要嘛立刻消失」，狀態永遠確定。

## Considered Options

曾考慮「進場嚴、出場鬆」的不對稱設計（進場用範圍市價 + FOK 要求價格品質，出場用市價確保成交），
依據是「進場失敗只是少做一天、零成本；出場失敗是部位過夜、有實質風險」。
使用者選擇兩邊一致用市價，以減少要記憶的行為種類。

FOK 也被排除：FOK 是全成或全不成，**出場整筆不成就是全部部位過夜**；IOC 至少能出掉手上有的量。
既然出場該用 IOC，進場也用 IOC 保持一致。

注意群益的限制：市價 `"M"` 與範圍市價 `"P"` **只能搭配 IOC 或 FOK**，不能 ROD
（官方文件：`BSTRbstrPrice;//委託價格(IOC and FOK，可用「M」表示市價，「P」表示範圍市價)`）。

## Consequences

- IOC 可能部分成交（3 口只成交 2 口）。解法不是額外邏輯，而是一句設計：
  **狀態檔記錄「實際成交口數」而非「委託口數」**，出場時據此送等量反向單，天然閉合。
- 接受滑價。微台流動性充足（2026/07/31 成交量 273,408 口，高於大台的 91,473），
  且進出場都在盤中時段，滑價風險有限。
- `sDayTrade = 0`（不標當沖）。標當沖可讓保證金減半，但若 13:40 出場失敗，
  部位會在只繳一半保證金的狀態下過夜，可能被追繳或強制平倉——等於在已知的失敗路徑上
  再加一層懲罰。口數由使用者自行設定，不需要靠槓桿擠資金效率。
